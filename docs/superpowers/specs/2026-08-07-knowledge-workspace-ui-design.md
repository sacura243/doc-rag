# 知答库知识库工作台界面设计

## 1. 目标

把当前较粗糙的问答页改造成“知识库工作台”首页：用户打开小程序后能立即理解产品用途、开始提问，并能看到上传资料入口。资料管理作为二级页面，负责导入、删除、重建和查看资料状态。

本次只调整微信小程序前端表现和交互，不改变已有 FastAPI 接口契约。

## 2. 设计方向

采用 A 方案“知识库工作台”，结合 GitHub 调研结果：

- 使用 `wechat-miniprogram/weui-miniprogram` 的 MIT 组件思路和微信原生视觉习惯。
- 参考 FastGPT、RAGFlow 的信息层级和来源引用方式，不复制其代码或受限许可内容。
- 保持白色为主背景，使用青绿色作为主操作色，灰黑色作为文字和边界色。
- 页面采用清晰的纵向信息流，不使用大面积渐变、装饰性光斑或营销式 Hero。

## 3. 页面结构

### 3.1 首页：知识库工作台

从上到下排列：

1. 顶部栏：产品名“知答库”和当前用户角色；不放目标城市或无关营销信息。
2. 欢迎区：一句用途说明“从企业资料中找到可信答案”，展示当前资料数和知识片段数。
3. 问答区：较大的多行输入框、示例问题和“开始问答”主按钮；提交时显示加载状态。
4. 快捷操作区：两个稳定尺寸的操作块，“上传资料”和“查看资料”。管理员可上传，普通成员只看到查看资料。
5. 最近资料区：显示最近导入的资料名称、片段数和更新时间；没有资料时显示空状态和上传引导。
6. 回答区：显示回答文本；有来源时显示资料名、页码和证据片段；无来源时不显示空的来源容器。

### 3.2 二级页：资料管理

1. 页面头部：标题、资料总数和“重建索引”按钮。
2. 管理员上传区：明确的上传按钮、支持格式和大小限制、上传进度条、失败原因。
3. 资料列表：每条显示文件名、知识片段数、导入状态和删除操作。
4. 空状态：无资料时直接提供上传操作和简短提示。
5. 成员权限：可以查看资料列表，但不显示上传、删除和重建操作。

## 4. 交互与状态

- 首页进入时请求资料摘要，失败时显示可重试错误，不让页面保持空白。
- 问答提交前拒绝空问题；提交中禁用重复提交；失败后保留用户问题并显示错误。
- 上传前校验扩展名和文件大小；多文件按顺序上传，进度按已完成文件数计算。
- 上传完成后刷新资料列表；索引重建完成后刷新资料列表并提示结果。
- 回答来源采用可折叠但默认可见的引用块，避免只给模型答案而无法追溯。
- 开发环境继续使用 `/auth/development`；正式环境由 `miniprogram/config.js` 切换到 `/auth/wechat` 和 HTTPS 地址。

## 5. 视觉规范

- 页面背景：`#f7f9fa`；内容区白色；边界 `#e2e8f0`。
- 主色：`#0f766e`；成功状态使用同色系浅底；错误使用 `#b91c1c` 和浅红底。
- 卡片圆角最多 8px（小程序对应约 16rpx 以下），阴影仅用于浮层或悬停反馈。
- 标题层级：页面标题 > 区块标题 > 辅助说明；避免在小卡片中使用过大的标题。
- 操作按钮使用图标或图标+短文本；上传、刷新、删除等操作不写成长句。
- 所有固定格式区域使用稳定的内边距、最小高度和换行规则，避免上传进度或长文件名造成布局跳动。

## 6. 数据与接口

继续使用现有接口：

- `GET /api/v1/documents`：首页资料摘要和资料页列表。
- `POST /api/v1/documents`：管理员上传并导入资料。
- `DELETE /api/v1/documents/{document_id}`：管理员删除资料。
- `POST /api/v1/documents/rebuild`：管理员重建当前工作区索引。
- `POST /api/v1/chat`：问答，返回 `answer` 和 `sources`。

不新增数据库表，不把服务端文件路径展示给用户。

## 7. 验收标准

- 首屏能在不进入二级页的情况下看到“上传资料”入口（管理员）和“查看资料”入口。
- 首页不再只有一张问答卡片，资料状态和最近资料可扫描比较。
- 上传 TXT/PDF/DOCX 时可看到进度；非法格式、空文件、超过 10 MB 时有明确提示。
- 问答回答下方能看到引用资料名和页码；无来源时不出现空白引用区。
- 成员无法通过界面执行上传、删除、重建；后端权限测试继续通过。
- 微信开发者工具本地编译通过，桌面端 API 健康检查返回 `{"status":"ok"}`。

## 8. 不在本次范围

- 不复制 FastGPT、RAGFlow、Dify 的前端代码。
- 不在本地开发阶段接入真实 AppSecret、支付、订阅或生产域名。
- 不重构后端 RAG 算法和向量数据库结构。
